STEP 1imports 即世界

模块能调什么，宿主说了算

WASM 里没有「系统调用」这个概念 —— 模块只能调宿主实例化时传进来的函数表

实例化：new Module(imports) · 没传 = 符号不存在
宿主传入的 imports 表module: wasi_snapshot_preview1
fd_write✓ 传入模块可以写 stdout
random_get✓ 传入模块可以取随机数
sock_accept✕ 不在表中模块的世界里没有这个函数
想联网？模块里根本没有 sock_accept 这个符号可调 —— 不是运行时被拦，是链接期就报错
「显式授予」的实现机制：宿主只把授权过的函数引用放进 imports
💡 世界的边界 = imports 表 —— 表里没有的，对模块来说从未存在
STEP 2线性内存

一维牢笼：越界即自爆

模块的所有数据住在一块有上限的独立内存里 —— 访问指令自带边界检查

越界访问 → trap 立即终止 · 无任意地址
⚠️ 越界 → trap
线性内存起点有上限 · 模块独占 · 指令级边界检查
🔒数据不能当地址用 —— 指令强类型，没有「把整数当指针跳过去」的通路
🎯控制流完整性 —— call_indirect 校验函数签名，跳不进任意代码
📤与宿主传数据 = 显式拷贝 —— 宿主读写模块内存是明面上的操作，没有暗门
所以 WASM 模块构造不出指向宿主内存的指针 —— 牢笼不是墙厚，是根本没有通往墙外的指令
💡 内存隔离不靠查权限表 —— 靠 ISA 层面就不给你那条指令
STEP 3能力即句柄

路径不是通行证，句柄才是

同一个「打开文件」，OS 进程和 WASM 模块的入口完全不同

OS：字符串就能尝试 open · WASM：没有句柄连入口都没有
📦 OS 进程
open("/etc/passwd") → 进内核 → seccomp 过滤器检查 → 命中白名单？放行 : 拦截

默认什么都能试，安全边界靠过滤器装上之后才出现

🔐 WASM 模块
宿主授予：fd=3 → /tmp/notes.txt fd_open(3, "notes.txt") ✓ fd_open(?, "/etc/passwd") —— 没有 3 号句柄指向它

拿到的是已打开资源的引用 —— 引用只能来自宿主返回值，无法伪造

能力模型的精髓：句柄不可伪造、不可猜 —— 路径字符串人人在手，句柄只有被授予的人才有
💡 OS 拦「调用」，WASM 连「发起调用的资格」都不给
STEP 4namespace 视图

OS 侧：给进程发一套假门牌

clone() 时带上视图开关 —— 内核按 namespace 过滤进程能「看见」的对象

CLONE_NEWPID / NEWNET / NEWMOUNT / NEWUSER…

PID 1 python
（只有自己 ——
独立网卡 · 独立挂载表）
🚪机制：clone(CLONE_NEWPID) 让内核为子进程建一套新编号空间 —— 访问内核对象时按视图过滤
🎚️cgroups 管额度：CPU/内存/IO 挂到组上限量，超限 OOM kill —— 防止吃光宿主机
👁️关键差别：进程依然共享同一个内核 —— 隔离的是视图，不是内核本身
「假门牌」的代价：内核攻击面还在 —— syscall 能不能发，才是下一道闸（下一屏）
💡 namespace 骗的是眼睛 —— seccomp 管的才是手
STEP 5seccomp 管道

内核入口的检查站

装上过滤器后，每一次 syscall 进内核都要先过一道 BPF 程序

按调用号 / 参数过滤 · 违规 SIGSYS
应用发起 syscall
→
BPF 过滤器调用号在清单？参数合法？
→
内核执行
✓ read / write / exit → 放行执行
✕ 清单外（如 mount）→ SIGSYS 击杀进程
与 WASM 的时序差别：OS 进程出厂就能发任意 syscall，安全边界在装上过滤器之后才出现（装之前有窗口）；
WASM 模块不存在这个窗口 —— 未授权能力从构造起就不可达
💡 一个是先给后拦，一个是先不给后给 —— 哲学差异写在构造里
