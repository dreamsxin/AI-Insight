一次前向，同时处理 整段输入。
算力打满，搬运只发生一次 —— 这是"便宜"的那一段。

prefill 的产物是 KV 缓存，不是文字。它决定你多久看到第一个字。

搬运时间 ≈ 不变，计算量 ≈ 1/N。

这一步重复几百次，所以 TBT 的每一毫秒都要抠。
03算术强度

每读一字节，能干多少活

这个比值，决定了一段计算到底卡在算力还是卡在带宽。

prefill · 一次算很多 token高
同一份权重，摊到很多 token 上
decode · 一次算一个 token低
同样的搬运，只换回一个 token
差了一个数量级。所以"把两种任务放同一张卡"注定互相拖累。
04屋顶线

芯片的屋顶，只有一条边可用

横轴是算术强度，纵轴是实际算力。斜线是带宽给的，平台是算力给的。

prefill 落在平台下 decode 卡在斜线上
decode 想变快，要么减少搬运（更大 batch、更小权重），要么换更宽的带宽。

07小结

两种饿狼，不该关在一个笼子

这一集只需要记住一件事：它们要喂的东西不一样。

🧮
prefill 饿算力

成批的 token 一次过，算术强度高，算力是瓶颈。

🚚
decode 饿带宽

每写一个字都要搬一遍权重，算术强度低，显存是瓶颈。

🔀
合成批能缓解，不能消解

批越大越省，但排队也越久，两种需求天然冲突。
