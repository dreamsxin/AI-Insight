STEP 1天生失忆

天生失忆

新会话开一场，模型对昨天发生的一切一无所知 —— 历史要靠调用方重新发

新请求 = 全新窗口 · messages 从零开始
🧑 用户 · 新会话
还记得昨天我们聊到哪了吗？
🤖 模型
我们的对话才刚开始 —— 我这边没有昨天的任何记录。
它没说谎 —— 窗口里真的只有这一句（呼应 04 期：每轮请求完整重发）
💡 模型天生失忆 —— 「记得」从来都是系统的事
STEP 2短期记忆

短期记忆

上下文窗口就是模型的「内存」—— 快，但小、贵、断电即失

main context ≈ RAM · 快 / 贵 / 会话结束即失
RAM · 上下文窗口
本轮用户刚问的问题
本轮刚检索回来的资料
本轮当前任务的工作状态
优点：随手可用、零延迟　代价：容量有限（02 期）、请求结束就没了
💡 窗口里的短期记忆：快，但小、贵、断电即忘
STEP 3长期记忆

长期记忆

把值得记的写到窗口外面 —— 像磁盘一样跨会话持久保存

external context ≈ 磁盘 · 慢一点 / 便宜 / 永久
💾 记忆库 · 跨会话持久化
memory_01用户偏好：喜欢简洁回答 + 代码示例
memory_02项目背景：技术栈 FastAPI + Vite
memory_03未完成任务：重构登录模块（上周三）
断电不失 · 下次会话按需「换入」窗口 —— MemGPT 的分页思想
💡 长期记忆存在窗口外 —— 需要时再「换入」，像操作系统的内存分页
STEP 4写入时机

写入时机

什么时候把东西写进记忆库？两条路线，各有代价

hot-path write · background write
⚡
热路径写入 hot-path

回复之前，模型用工具显式记一条（「记住：用户偏好简洁」）—— 立即生效，但增加响应延迟

🌙
后台写入 background

对话结束后，后台进程悄悄总结入库 —— 零延迟，但记忆稍滞后、需要触发逻辑

关键记忆走热路径，琐碎记忆走后台 —— ChatGPT 的「记忆」就是热路径写入
💡 两种写入各有代价 —— 按记忆的重要性分流
STEP 5检索与注入

检索与注入

新问题进来时，从记忆库里捞出相关的几条，塞回 system —— 模型就「想起来了」

recall(question) → top-k memories → inject
💬 新问题
相关记忆 ×2
💾 记忆库
塞回 system
📜 窗口
system 消息 · 注入后
你是助手。以下是关于该用户的已知记忆：
· 偏好简洁回答 + 代码示例
· 项目技术栈 FastAPI + Vite
不是全塞回去 —— 窗口预算有限（02 期），只捞最相关的几条
💡 记忆不是全量回灌 —— 只捞相关的几条塞进窗口
STEP 6压缩与遗忘

压缩与遗忘

历史逼近上限时，把旧对话总结成高保真摘要，用摘要重启新窗口

compact: history 5.8k tok → summary 1.6k tok
压缩前5.8k tok
压缩后1.6k tok
保留：架构决策 保留：未解决问题 保留：用户偏好 丢弃：工具原始输出 丢弃：冗余来回
先保召回，再提精度 —— 过度压缩会丢「当时不起眼、后来才发现关键」的细节（Anthropic）
💡 压缩 = 保留结论、丢弃原料 —— 召回优先于精简
STEP 7三类记忆地图

三类记忆地图

像人脑一样分库管理 —— CoALA 框架把长期记忆分成三类

semantic · episodic · procedural（CoALA）
🧠
语义记忆 semantic

事实与偏好：「用户是前端工程师」「喜欢深色主题」—— 用来个性化回答

🎬
情景记忆 episodic

过去的行为序列：「上次这类任务是这样做的」—— 用来做少样本示范

🛠
程序性记忆 procedural

怎么做任务：藏在提示词与代码里 —— 最稳定，也很少被自动改写

不同记忆类型适合不同写入与检索策略 —— 先想清楚「记什么」，再选「怎么记」
💡 像人脑一样分库管理—— 而不是一个口袋全塞进去
RECAP全景

失忆 → 分层 → 写入 → 检索 → 压缩 → 分库

天生失忆→内存+磁盘分层→写入分流→检索注入→压缩遗忘
🧊
窗口 = RAM

快、贵、断电即失 —— 只放当前正在用的东西

💾
记忆 = 磁盘

跨会话持久化，按需换入 —— MemGPT 用操作系统的思想管上下文

⚖️
写入有代价

热路径即时但加延迟，后台省心但滞后 —— 分流是工程的关键
