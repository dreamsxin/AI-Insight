STEP 1组装 messages

组装 messages

你发出的这句话，会先和 system 人设、历史对话一起，打包成一个 messages 数组

messages = [system, ...history, user_msg]
system你是 AI 原理科普助手，用生活化的比喻讲解技术概念。
user神经网络是什么？
assistant把它想成一台「自动调旋钮的机器」……
user那它又是怎么训练出来的？
messages.length = 4 · 每轮请求都会完整重发
💡 LLM 没有记忆 —— 每次请求都要把整个对话历史重新带上
STEP 2分词 Tokenize

分词

messages 先被送进分词器，切成模型认识的最小单元 —— token

tokens = tokenizer.encode("那它怎么训练？")
那它怎么训练？
那#21535
它#2831
怎么#4248
训练#50112
？#151645
→ [ 21535, 2831, 4248, 50112, 151645 ]
一个「字」不等于一个 token —— 模型只认编号，不认文字
💡 模型眼里没有「字」，只有一串数字编号 —— 分词是把文字翻译成数字的第一步
STEP 3预测下一个 token

预测下一个 token

模型根据全部上文，给词表里每个候选算一个概率，挑出最合适的下一个 token

next_token = sample(logits) # 词表 15 万+，只选 1 个
…神经网络的训练，就是
调整41.6%✓
学习23.9%
训练12.2%
反馈7.4%
选中的 token 接回句尾 —— 再预测下一个，如此往复
💡 看似一气呵成的回答，其实是把「预测下一个 token」重复了几十上百次
STEP 4流式生成

流式生成

每生成一个 token 就立刻推送给你 —— 这就是「打字机效果」的来源

for chunk in stream(): yield chunk
assistant · streaming
神经网络的训练，就像反复微调收音机的旋钮，直到声音清晰。
chunk #12 已送达 · 86 tok/s
💡 流式不是「生成完再加速播放」—— 而是 token 刚出生就被推送出来
STEP 5多轮循环

多轮循环

这段回答会被追加进 history —— 下一轮请求，模型就「记得」之前聊过什么

history.append(assistant_msg) # 下一轮随请求重发
💬 用户提问
📦 组装 messages
🧠 生成回答
📚 追加 history
对话轮次循环round += 1
第 1 轮1.2k tok
第 2 轮2.8k tok
第 3 轮4.1k tok
历史越滚越大 —— 长对话更慢、更贵，直到触及上下文上限
💡 模型从未「记住」你 —— 记忆只是每一轮重新发一遍的完整历史
RECAP全景

一句话的旅程

从点击发送到流式回答，背后是一场循环往复的接力

组装 messages→分词→预测→流式生成→追加 history
🧩
无状态设计

模型本身不存对话，天然支持水平扩展；历史由调用方自由管理、裁剪、持久化

📏
上下文是硬约束

所有历史 + 新回答都要塞进上下文窗口，超了就必须截断、压缩或摘要

🔁
逐 token 生成

「预测下一个词」重复千万次，涌现出推理、翻译与写代码的能力
