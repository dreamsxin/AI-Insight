STEP 1OS 三件套

容器的隔离，是三样东西叠出来的

不是一堵墙 —— 是「看不见、用不超、拦得住」三道机关的组合

namespace · cgroups · seccomp
🚪
namespace · 发一套假门牌

PID / 网络 / 挂载 / 用户等八种视图隔离 —— 进程以为自己是 1 号、独占整台机器，其实被内核骗了

🎚️
cgroups · 限个额度

CPU / 内存 / IO / 进程数划上限 —— 沙箱里的代码再疯，也吃不掉宿主机

🚧
seccomp · syscall 白名单

内核调用按清单放行；严格模式只留 read/write 等 4 个调用，违规直接击杀

注意这套模型的本质：内核是共享的 —— 靠「规则 + 过滤」拦住坏调用，所以叫过滤式
💡 过滤式的安全上限 = 内核攻击面的大小
STEP 2更强隔离

从容器到微型虚拟机

担心内核漏洞？隔离光谱往右走 —— 每一步更硬，也更贵一点

容器 → gVisor → microVM
容器

namespace + cgroups + seccomp 直达宿主内核 —— 最快最轻，隔离最薄

gVisor

用户态内核「海关翻译官」：应用说 syscall，Sentry 先审查翻译再转述，坏话扣下 —— 内核攻击面大幅缩小

microVM

Firecracker：只模拟 5 个设备的极简 VM，125ms 启动、每台 <5MiB，撑起 AWS Lambda 每月 15 万亿次调用

Agent 沙箱服务的真实选择：E2B 用 Firecracker、Modal 默认 gVisor —— 都是「跑模型生成的代码」的专用笼子
💡 隔离与兼容是一对滑块 —— 越往右越硬，兼容越要打折
STEP 3WASM 能力式

出厂白卡，逐项授权

WASM 反着来：模块初始零权限 —— 每一项能力都要宿主显式授予

no ambient authority · 越界即 trap 自爆
读文件 /tmp/notes.txt授予 ✓宿主点名开放这一个路径
访问网络未授 ✕想联网？宿主没给就是没有
系统调用无此概念 ✕没有任意 syscall —— 走 WASI 才有最小能力
内存越界立即 trap线性内存有上限，越界当场终止
✓ 授予后模块获得：读 /tmp/notes.txt —— 仅此而已（新员工空白工卡：进每间机房都要刷卡）
附赠两个红利：一次编译跨架构（镜像可只有 3MB）、冷启动微秒~毫秒级 —— 容器是秒级
💡 过滤式靠拦，能力式靠没给 —— 后者的默认态更安全

STEP 5怎么选

Agent 场景的两条路

按「你要跑什么代码」选笼子，而不是按「哪个更新」选

先看依赖，再看启动频率，最后看隔离要求
📦 跑 Agent 生成的 Python？

选 OS 沙箱 / microVM（E2B、Modal 这类服务）—— pip 依赖随便装、完整 Linux 环境；配合 09 期闸门做网络白名单

🔐 轻量插件 / 边缘函数？

选 WASM —— 冷启动微秒级、默认零权限；用户上传的第三方插件，能力式沙箱是最稳的容器

混合形态也是常态：容器里跑 Wasm 运行时（containerd shim）—— 用容器管依赖，用 WASM 管隔离
Docker 创始人 Solomon Hykes 曾感叹：「如果 WASM + WASI 在 2008 年就存在，我们根本不需要创建 Docker。」
