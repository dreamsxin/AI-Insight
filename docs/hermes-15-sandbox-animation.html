STEP 2沙箱双边界

先关进盒子，再谈放什么出来

编码 Agent 的沙箱（2025-10 起成为主流形态）同时圈住两件事：文件系统与网络

📁 文件系统隔离

Agent 只能在工作区（worktree/临时目录）内读写；系统目录、其他项目默认不可见；要越界先申请，由 hook（14 期）裁决

workspace/worktree 隔离越界 → 申请

🌐 网络域名白名单

出网默认拒绝，只放行明确登记的域名；内网、元数据服务、未知 IP 全部不可达 —— 即使被投毒也无法把数据外传

allow-list默认拒绝出网阻断 exfiltration
💡 这比 09 期的「危险动作名单」更根本：名单防已知坏事，边界让未知坏事也做不成

STEP 4Auto 模式：两个互相看不见的裁判

分类器只看裸调用，不看辩解

放开自动执行后，由独立安全分类器在两端把关 —— 它们刻意不看模型的解释，防止「投毒内容说服裁判」

📥 输入端探针

扫描刚拿到的工具输出/网页内容：是否藏着注入指令、可疑链接、诱导文本

看：工具结果原文
不看：模型的辩解

📤 输出端分类器

只看用户消息 + 裸工具调用：这个动作本身危不危险，与模型说了什么无关

看不到：投毒网页的内容
→ 注入文字无法「向裁判求情」
双裁判 + CoT 复核把浏览器注入攻击成功率从 23.6% 压到 11.2%（实测），误报率仅 0.4%
💡 与 09 期同一原则的升级：数据 ≠ 指令 —— 裁判隔离内容，恶意网页再能说会道也碰不到裁决依据
