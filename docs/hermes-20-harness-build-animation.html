STEP 1裸模型的三个缺口

只会说话的模型，不是 Agent

直接调用 LLM 只有「一问一答」。行业公式先立起来：Agent = Model + Harness —— 缺的部分全在 Harness

🗣️
不会动手

说得出「2+3 等于 5」，但从不真正计算；碰不到文件、网络与数据库

🫥
没有状态

每次调用从零开始，任务中断即全部丢失，跨会话什么都不记得

🎰
不可信任

没有步数与预算上限，没有轨迹可审计 —— 失败了连原因都查不到

Agent = Model（推理） + Harness（其余一切工程）
💡 18 期说「Harness 决定上限」—— 这一集把上限一块一块垒出来，每步都有可运行代码
STEP 2第一块积木：工具循环

模型提案，宿主执行

Harness 的核心是一条循环：模型发出工具提案，宿主真实执行，把结果作为观察塞回消息，直到模型不再要求工具

while 无最终回答: think → tool_call → 宿主执行 → observe
think模型提案
add(17, 25)
→
act宿主执行
返回 42
→
observe结果入消息
再次推理
↻ 直到 tool_calls 为空 → 收敛作答「17 加 25 等于 42」（5 条消息轨迹）
模型只有提案权说要调什么工具、传什么参数
宿主握执行权真跑、可拦截、可审计 —— 安全边界在此
💡 这一条循环补上「不会动手」—— Hermes 04 期的主循环、本仓库 Agent.run() 都是它
STEP 3第二块积木：保险丝

失控的循环是台烧钱机

模型会用完全相同的参数反复撞同一堵墙（temperature=0 也救不了）。护栏必须长在代码里

read_config("config.json") ×2 同参数 ×3 同参数 ⛔ 熔断
🔢
max_steps步数上限
防空转
💸
token 预算总量封顶
防烧钱
🔁
重复检测同工具同参数
连续 3 次即断
三道闸全部写在宿主代码里，模型既看不到也关不掉 ——
熔断后升级而非硬扛：问人 / 换路 / 如实报 failed（避坑 02 期）
💡 保险丝补上「不可信任」的一半 —— 另一半靠可观测，见 STEP 5
STEP 4第三块积木：错误回填

失败不是异常，是塞回循环的观察

工具报错时 Harness 不崩溃，把错误文本作为观察回填 —— 模型下一轮亲眼看到失败原因，自己修正重试

尝试 1

read_config("config.json") → FileNotFoundError：文件不存在（也许叫 config.yml？）

观察

错误文本作为 role=tool 消息回填 —— 模型读到线索

尝试 2

read_config("config.yml") → 成功返回 app_port=8000

错误信息越具体，自救成功率越高；宁可如实报错，不许编一个「已完成」
（Hermes 11 期的铁律，在生产 Harness 里是一条 if 语句）
💡 工具错误回填 = 给模型一双看见失败的眼睛 —— 这是 11 期「错误恢复」的最小实现
STEP 5第四块积木：轨迹与检查点

黑盒变白盒，崩溃可续跑

最后补「无状态」与「不可审计」：每步事件写 JSONL 轨迹，消息历史落盘即检查点

tool_call   {"name": "get_weather", "arguments": {"city": "杭州"}}
tool_result{"content": "12–19°C 小雨", "is_error": false}
llm_response{"content": "杭州今天 12–19°C 小雨…", "step": 2}
finished   {"output": "…出门带伞。", "steps": 2}
📜 trace.jsonl逐步事件落盘
失败可回放、可评测（避坑 04）
💾 checkpoint.jsonmessages 序列化
新会话带着历史续聊
学术前沿 SafeHarness 建议每 3 个执行步骤做一次 checkpoint，可回滚到最近可信状态
💡 「会话即事件日志」（18 期）的最小实现：状态外置，进程随时可死可换
STEP 6生产里的 Harness 长什么样

Anthropic 的长任务配方

Anthropic（2025-11）让 Agent 跨多个 context window 连续工作数小时：两大失败模式 —— one-shot 做完全部 与 过早宣布完工

🏛️ 两段式 Agent + 清单门禁

  • Initializer 首个会话搭环境，把需求展开为 200+ 项 feature 清单（JSON，初始全部 passes: false）
  • Coding agent 每个 session 只做一个 feature，测试通过才能翻 true
  • progress 文件 + git log 让新会话快速恢复现状；init.sh 一键启动
  • 清单用 JSON 而非 Markdown —— 模型更不容易擅自改动
工具循环本仓库 backend/app/agent/ 的 Agent.run()
保险丝/回填Guardrails 三道闸 + is_error 观察
轨迹/检查点on_event 事件流 + messages 序列化
亲手跑一遍examples/agent-harness-demo/ 五个脚本（离线可运行）
💡 生产 Harness 没有魔法 —— 就是这四块积木的工业级放大，加上清单与门禁
