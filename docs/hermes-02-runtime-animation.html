STEP 1会话创建

会话创建

任务通过适配层的第一件事：创建会话 —— 之后所有状态都挂在它身上

session = create_session(entry="cli")
session · 运行时档案袋
session_ids_7f3a
entrycli（从哪扇门进来的）
created14:02:11
statusrunning
session s_7f3a · 一切状态的挂载点
💡 会话是「档案袋」：入口是谁、聊到哪了、用了什么工具，全记在这一个 ID 下
STEP 2上下文绑定

上下文绑定

会话创建后立刻绑定上下文 —— 把 system 人设、历史消息、新任务装进 messages

messages = [system, ...session.history, user_msg]
system你是 Hermes，专业、安全、合规的自动化助手……
history上一轮：已分析 auth 模块结构，找到 3 个候选函数……
user处理用户登录的函数在哪？
绑定到 session s_7f3a
💡 「绑定」不是复制 —— 换一扇门进来的任务，绑定的可以是同一个档案袋
STEP 3工具清单共享

工具清单共享

不管你从 CLI 还是微信进来，Agent 手里的工具箱是同一个

tools = [bash, read_file, …] · 一次注册，全局可用
bash 执行命令 read_file 读文件 edit_file 改文件 grep 文本搜索 codegraph_query 代码图谱 browser_* 浏览器操作
工具 schema 只注册一次 —— 所有入口的任务共用同一份清单
💡 工具不认入口 —— 同一个 codegraph_query，终端能用，微信里一样能用
STEP 4记忆与压缩

记忆与压缩

历史越滚越长，运行时的另一项工作就是压缩 —— 昂贵的上下文只留精华

if tokens > LIMIT: history = summarize(history)
第 1 轮1.2k tok
第 2 轮2.8k tok
第 3 轮4.6k tok
触发上限 · 运行时自动压缩⌄
压缩后1.4k tok
摘要替换原文 —— 关键结论保留，过程细节让路
💡 压缩发生在运行时 —— 五个入口共享的是同一条被压过的记忆，而不是五份
