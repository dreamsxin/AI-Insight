STEP 1为什么分布

串行太慢，上下文会互相污染

把大任务拆给一队 Agent：每个都有自己的干净上下文，并行开工只回摘要（09 期的实战化）

Anthropic 深度研究系统实测：3~5 个 subagent 并行
✕ 单 Agent 串行
✓ 一队并行
+90.2%准确率提升
-90%研究时间
×15token 花费
多 Agent 的账要算清楚：并行是拿 token 买时间和准确率 —— 简单问题一只 Agent 足矣
💡 分布不是架构时髦 —— 是拿 token 换并行的一笔交易

💡 名片即契约 —— 能力、端点、认证，三样说清才能合作
STEP 3任务生命周期

委托出去的任务，状态要管住

A2A 的 task 有明确状态机 —— 中途还能举手要补充输入

HTTP + JSON-RPC · 流式走 SSE
submitted→ working→ input-required?→ working→ completed/ failed
📦交付物叫 artifact —— 带版本演进，改了有据可查
⛔终态不可重启 —— 要继续只能同 contextId 开新任务
🕶️需要授权时任务会停在 auth-required —— 等 09 期的闸门点头
07 期的批量队列是「自家后院」；A2A 是跨组织委托的公共协议 —— 两种场景，两套语言
💡 委托不是发完就忘 —— 每个状态都要有人认领
STEP 4崩溃恢复

不存内存快照，重放历史

Temporal 式持久化执行：把「发生过的一切」记成事件流 —— 崩溃后重放代码，原地满血复活

事件历史 = 唯一事实源 · Celery 扔队列，Temporal 管全程
EVENT HISTORY · job-07
01task_received(分析年报)✓
02activity: fetch_pdf() → 结果已存✓
03activity: summarize(p.1-40) → 已存✓
04💥 worker 宕机 —— 剩余进度丢失
05新的 worker 接手 → 重放事件历史
06重放到 03 直接复用结果 → 从 04 续跑✓
像游戏录像回放：不恢复内存快照，而是重演每一步操作
外部调用的结果都记了账 —— 重放时直接复用，天然幂等（11 期）
💡 分布式的底气 —— 不是不出故障，是故障后能续
STEP 5调度细节

队列之外的四件小事

把任务派出去只是开始 —— 分布式的功夫全在这些边角

心跳 · 幂等 · checkpoint · 按复杂度派单
心跳租约worker 定期续租 —— 超时未续视为掉线，任务自动重新分配给活着的同伴
幂等重试同一个任务重跑不能产生两个结果 —— 写操作带唯一键，重试只续不重做（Stripe 式幂等）
checkpoint长任务定期存档、失败从断点 resume —— 别让三小时的任务从头再来
按量派单简单问题 1 Agent + 几次工具调用就够 —— 别用一队人去查一个电话号码
这四件与 11 期的错误恢复是一体两面：单机靠循环自救，集群靠调度自救
💡 分布式的功夫在边角 —— 心跳、幂等、断点，一个都不能省
