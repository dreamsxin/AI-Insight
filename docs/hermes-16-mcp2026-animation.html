STEP 1回到 2024 年的首版

先握手，再开两条通道

03 期讲的形态：客户端先 initialize 交换能力，Server 把使用指南放进 instructions，传输只有 stdio 与 HTTP+SSE

2024-11 · 首版

有状态会话 + 双传输

initialize 握手capabilities 协商instructions 注入stdio（本地）HTTP + 独立 SSE 通道
↓ 真实部署暴露问题 ↓
🌐 远程化困难SSE 要维持一条独立长连接，负载均衡与无状态云服务不友好

STEP 22025-03 · Streamable HTTP

一条通道，能推也能问

传输层合并为单一 HTTP 端点：同一个 POST 地址，普通响应返回 JSON，需要流式时在响应里开 SSE

旧：HTTP + SSE

POST /messages　发请求
GET /events　另开长连接
两条通道要自己关联
断线重连复杂

新：单端点 ✓

POST /mcp（唯一地址）
普通回复 → JSON
需要流式 → 响应内 SSE
可无状态部署、好做负载均衡
旧的独立 SSE 传输随后被正式标记弃用（Deprecated）；stdio 保留给本地进程 —— 一套语义，两种部署形态
💡 和 15 期的思路同源：少维护一条长连接，就少一份状态与故障面
STEP 3授权：令牌要能被管住

远程工具，先解决「你是谁」

MCP 授权基于 OAuth 2.1 + PKCE：桌面/CLI 也能安全完成登录，且令牌与目标服务绑定

Client 发现授权端点→ PKCE 免密跳转→ 用户同意 scope→ 拿到 access token→ audience 绑定
🎯 audience / 资源指示令牌只能用于声明的 Server，防止「拿着 A 的令牌去调 B」—— 令牌挪用（confused deputy）被从协议层堵住
🔄 增量授权需要新权限时再弹一次同意；支持设备流与令牌刷新，CLI 不必让用户手抄密钥
与 15 期的凭证代理呼应：授权标准化之后，「哪个工具能动哪份数据」才可以审计
💡 stdio 本地进程可继续免授权 —— 协议按信任边界分级，不搞一刀切
STEP 4Tasks · 长任务一等公民

慢任务：先给句柄，再慢慢跑

2025-11 加入 Tasks 扩展：Server 可以把长任务做成持久对象 —— 这正是 Hermes 07 期自建的三态回传

working进行中→ input_required等人补料→ completed产出 artifact / failed失败有原因cancelled可取消
📮 两种拿结果方式轮询 task 状态，或接受 Server 的进度/完成推送；断连后凭 task id 接着查
🙋 input_required任务中途缺信息可正式「挂起等人」—— 与人在回路（HITL）的通用协议，不再各自发明
💡 Hermes 07 的 working/input_required/completed 与官方状态机几乎一一对应 —— 好模式被协议收编
STEP 52026-07 · 无状态化大改

取消握手：每请求自带身份证

最新版删除 initialize 会话握手 —— 协议版本与能力改由每个请求的 _meta 自带，Server 可纯无状态水平扩展

− POST initialize（建会话、协商能力）
− 服务端保存 session 状态
+ 每请求 _meta：protocolVersion / capabilities
+ MRTR：服务端用 input_required 反向要补充
📇 能力即名片没有握手，就没有「会话开始」的专门注入点 —— 工具说明改为按需发现（呼应 13 期 Skills 名录）
⚡ 顺序也值钱规范建议工具列表保持确定顺序，以提高前缀缓存命中率（15 期 prompt caching）
💡 方向一以贯之：协议越来越像 HTTP —— 无状态、可缓存、可水平扩展（具体字段以最新规范为准）
