01 · 格子数

一个 block 能服务几路会话

get_num_state_slots = int(max_num_seqs × ratio) + 1
格子的总数在分配那一刻就定了。

# cache_engine.py get_num_state_slots = int(max_num_seqs × ratio) + 1
➕
为什么多加 1

给"正在写入但还没登记"的那一路留一个空位——不加这 1，满载时的写入会踩到别人的格子。

📐
为什么乘 ratio

压缩层一份 state 服务多路请求——格子数不等于会话数，是按压缩比折算过的。

容量的第一层：格子总数是公式定死的，不是"能装就装"。
02 · 分区

一块里，先分两种住户

stored（要落盘的 SWA）在前，dropped 在后。
落盘时按长度截断，就自然排除 dropped。

stored要落盘 · 低地址
dropped用完即弃 · 高地址
YOCO consumer SWA 之外的正式数据截断线在这 · 不用挑着写
布局即策略："谁要留"用地址表达，落盘逻辑里就不再出现 if
数据出处：cache_engine.py L210–L300 的 StateBlock 分区。
03 · 零头

对齐吃掉的那部分

每层 SWA 按 32 B 对齐；含 SWA 时整块按
lcm(32, 每 token 字节数) 对齐。

项目体量
每层 SWA 对齐零头几 KB
× 层数× 80
× 每机卡数× 8
一台机器上被零头吃掉的GB 级
对齐不是为了好看——是为了 TMA / 拷贝一次拿整段。
零头是买"整段搬运"的价钱
单片看是零头，乘上层数和卡数，就是预算里的一行。
