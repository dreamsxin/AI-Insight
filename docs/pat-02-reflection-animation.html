STEP 1一稿成型

第一稿，往往带着三种伤

模型一次生成完就交，常见三类毛病：算错、漏项、不合规 —— 它不是不会，是没人让它回头看

USER · 核算并回复v1 初稿
30 人参会：场地 8000 元，茶歇每人 80 元，专家费 6000 元。请给客户发一封报价邮件，金额用万元。
总费用 = 8000 + 80×30 = 1.04 万，含茶歇报价如下…… 顺颂商祺！
🧮 算错：专家费 6000 漏加，应为 16400 元 = 1.64 万
📋 漏项：没写费用明细与有效期，客户没法内部报批
🧑‍💼 不合规：商务邮件缺称呼与署名，「顺颂商祺」前缺落款
💡 一稿的错不是能力问题 —— 是缺一道「回头检查」的工序
STEP 2换顶帽子

同一个模型，当一回审稿人

Reflection 不调新模型 —— 把初稿喂回去，换一条审稿 prompt，让它以 Critic 身份输出结构化问题清单

draft → critic_prompt → [{问题, 位置, 严重度}]
✍️ v1 初稿writer 视角
→
🧠 同一个 LLM换上 critic 帽子
→
🔍 问题清单结构化 · 可执行
WRITER PROMPT
「你是商务助理，
根据费用写报价邮件，
金额用万元。」
CRITIC PROMPT
「你是苛刻的审校：
逐项复核算术、明细、
格式合规，只报问题，
按严重度排序。」
CRITIQUE · 3 ISSUES
[高] 总额漏算专家费 6000，金额错误
[中] 缺明细拆分与报价有效期
[低] 缺称呼 / 落款，格式不完整
💡 模型挑别人毛病，往往比自己一次写对更在行
STEP 3带着批注改

问题清单，就是修订说明书

把初稿 + 审稿意见一起喂回，模型逐条改 —— 批注让修订有的放矢，而不是重抽一次彩票

revise(draft, critique) → v2
V1 · 初稿
总额 1.04 万
含茶歇报价如下……
顺颂商祺！
V2 · 修订稿
← 按 [高] 重算
合计 1.64 万（明细如下，报价 7 日有效）
尊敬的客户……（落款：商务组）顺颂商祺
🔁 还不满意就再来一轮：v2 → 审稿 → v3 …，每轮只带「稿 + 批注」
💡 审稿与写作分开两轮调用 —— 每顶帽子只干一件事，都干得更好
STEP 4迭代与刹车

越改越好，但有天花板

每轮修订都在涨分，涨幅却快速递减 —— 所以 Reflection 必须自带停止条件，不然就是烧钱机（参考 dev-02 保险丝）

💡 Reflection 是用 token 买质量 —— 买够了就要会停
STEP 5什么时候值得

不是所有任务都配一轮审稿

可验证、有客观对错的任务，Reflection 收益最大；随口闲聊也要审三轮，纯属给账单添砖加瓦

✓ 审稿很划算
  • 数学计算 / 数据核算，能重算验证
  • 写代码，能跑测试、能 lint
  • 翻译 / 长文写作，有格式与事实可核
  • 结构化输出，能对着 schema 逐字段查
✕ 审稿是白烧钱
  • 闲聊、寒暄、创意发散
  • 一步就能答的简单事实
  • 没有评判标准的开放口味题
  • 实时性极高、延迟敏感的回复
📌 注意区分：Reflection 是模型自己当裁判，可能自我感觉良好 —— 上线前的客观验收仍要靠独立评估集（dev-04 期），两者是互补，不是替代
💡 能客观验证的任务才值得反思 —— 裁判也得有尺子
RECAP全景
