01老办法

共享一个随机数流

批量推理里最自然、也最坑的做法。

ANTI-PATTERN
全局 RNG

谁先取随机数，谁就拿到不同的一段。batch 一变，每个请求分到的数全变。

PATTERN
按序列取随机数

随机数由「种子 + 位置」算出来，取不取、取几次，都不影响结果。

差别只有一个：随机数是流，还是地址。

一旦把随机数当成「地址」，批处理就不再是副作用的来源。
02换成地址

seed + position → 同一个字

采样变成一次纯函数调用。

输入 1seq_seed + 输入 2position → kernel 内算随机数
→ 逆变换采样 → 输出token 下标
机器 Abatch=1 · 单独跑「的」
机器 Bbatch=64 · 第 41 行「的」
机器 Cbatch=8 · 重试一次「的」
不同机器、不同 batch、重试一次 —— 都吐同一个字。
03怎么测

三个断言就够了

这个性质是可以被测试守住的。

# 1. 跑两遍 assert equal(again, ref) # 2. 打乱行序 out = sampling(probs[perm], seed[perm], pos[perm]) assert equal(out, ref[perm]) # 3. 逐行单独跑 for i: assert equal(sampling(row_i), ref[i])

第三条最狠：它把「batch 不变」直接压成 n 次单例调用。

工程上，这种测试比任何文档都更能防止回归。
04与采样参数

温度、top-p 都还在这儿

确定性只是把「随机源」换掉，不是把概率抹平。

步骤 1
改概率

温度缩放、top-k / top-p 截断，得到一个分布。

步骤 2
用固定的随机数反解

拿 seed+pos 算出的均匀随机数，去反查累积分布落在哪个 token。

性质
概率为零的永不采样到

这也是契约里那句「zero-probability columns are never sampled」。

所以同一个 seed 跑两次，连「多想了一会儿」的中间态都一致。
