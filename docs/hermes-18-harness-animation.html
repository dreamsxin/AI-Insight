STEP 1brain / hands 解耦

决定成败的，常常不是模型

2026 年 Agent 平台开始把架构明确拆成两层：大脑只负责推理与决策，其余全部是可替换的脚手架

🧠 大脑（模型）

  • 无状态：每次只看到 messages
  • 只有提案权，不能真执行
  • 不记得上一个会话

🎛️ harness（脚手架）

  • 主循环、工具注册与执行
  • 上下文管理、预算/步数闸门
  • 权限、沙箱、hooks、重试与审计
Hermes 01–17 期讲的每一个机制 —— 适配层、权限闸、瘦身、Skills、思考预算 —— 全部属于 harness，不属于模型
同一模型配上不同脚手架，表现差距可以大过换一个模型
💡 选型只看模型分数是旧观念：模型决定下限，harness 决定它在真实环境的上限
STEP 2会话即事件日志

崩溃了，就让日志倒带

把 harness 做成无状态的关键：会话不是内存里的对象，而是一条只追加（append-only）的事件流

user_msg → assistant_msg → tool_call → tool_result → …（只追加，不改写）
[09:01] user 把周报整理成待办
[09:01] assistant tool_call: read_file
[09:02] tool_result …1.2k tokens…
[09:03] assistant tool_call: edit_file　⚠ 进程在此崩溃
事件日志落盘→ 新 harness 重放事件→ 从断点继续
这正是 15 期 PagedAttention「无状态、可重放」思想在 Agent 侧的对应：状态外置到事件，进程随时可以死、可以换
💡 检查点不是「保存内存快照」，而是 保存事件 + 能从事件重建状态（durable execution 的核心）
STEP 3后台 Agent

任务不必盯着跑完

2025 下半年起，编码 Agent 可以脱离当前会话在后台工作：独立工作区、可随时 attach、空闲时挂起

● bg/修登录 · running ● bg/写测试 · completed ● bg/调研框架 · suspended
📁 独立 worktreegit worktree add
每个后台任务一份隔离工作区与分支，互不踩脚（呼应 09 期隔离原则）
🔌 可 attach / 可挂起空闲时挂起到磁盘、释放算力；用户随时连回去看进度、插话纠偏，重启后接着跑
📨 事件驱动新消息、工具结果、定时器都能唤醒任务 —— 与 H16 的 MCP Tasks、H07 的三态回传是同一套语义
👥 多任务看板多个 Agent 并行 + 人工在关键节点审阅 —— 但按 H17 的结论：默认仍是单 Agent，后台只是「异步化」
💡 后台化的本质：把「人盯着 Agent」变成「Agent 完成或卡住时来找人」
STEP 4长任务的经济账

编排复杂度，要花得值

Agent 任务从几分钟走向几小时，成本结构也变了：钱主要花在多轮重复的上下文，而不是模型调用费

20min / $9
单个长任务 Agent 自主跑
典型中等复杂度
6h / $200
复杂多步任务全程
编排 + 多轮重发上下文
编排价值随模型代际递减：模型越强，越少需要复杂的规划器/评审器/多角色分工（H17）
早期靠 harness 补的能力，正在被模型内化 —— 每一代模型都值得重新审视：这层脚手架还要不要
省钱的仍是老三件：上下文压缩（02/05 期）、子代理隔离（AI 09）、工具结果瘦身（Hermes 05）—— 任务越长，复利越狠
💡 评估长任务别只看「跑没跑完」：要看 token/美元/墙钟时间三个口径一起算
STEP 5durable execution

会等人的任务，才像员工

生产级 Agent 平台（2026 年成型）把会话本身做成持久事件日志：harness 无状态、崩溃从事件恢复、人在任意节点接入

任务启动→ 工具调用→ input_required：等人审批/补料→ 事件落盘，进程可退→ 人回来 → 重放续跑
🧯 崩溃恢复事件重放保证「调用过的工具不重复、已完成的步骤不丢失」
🧑 HITL 一等化等待人不是异常分支，而是任务状态机里的正常一站（H16 Tasks 同款）
🪪 凭证不入库重放时经代理重新取凭证（H15），日志里不留密钥
💡 Hermes 11 期说「会自救，才配被托付」—— 会等人、会断点续传，才配进生产
