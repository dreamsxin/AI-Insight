STEP 1初始状态

初始状态

用户输入指令 —— 主循环的燃料 messages，此刻只有一条

messages = [{"role": "user", "content": …}]
user帮我打开杭州市气象局官网，看看今天天气。
messages.length = 1 · 主循环尚未开始
💡 循环的燃料是消息历史 —— 一切都从这一条 user 消息开始
STEP 2步骤 A · 亮菜单

亮菜单

Hermes 把对话历史和 MCP 工具菜单打包发给 LLM（DeepSeek）—— 老板只看菜单点菜

deepseek_api_request(messages, tools=mcp_tools_schema)
🤖 Hermes
messages + tools
🧠 DeepSeek
请求体 · 随历史一起发送的工具清单
{ "messages": […], "tools": [
  { "name": "browser_open_url" },
  { "name": "browser_extract_text" } ] }
✓ 菜单随请求亮出 —— LLM 只能点菜，不能下厨
💡 LLM 从不直接碰工具 —— 它只看到这份「菜单」，并从中选择
STEP 3步骤 B · 拦截意图

拦截意图

LLM 的回复带着 tool_calls —— 这不是答案，Hermes 拦下，不外发给用户

if not response_message.get("tool_calls"): return …
assistant 消息 · 带工具调用意图
{
  "role": "assistant", "content": null,
  "tool_calls": [{ "function": {
    "name": "browser_open_url",
    "arguments": {"url": "hz-weather.gov.cn"} } } ]
}
⚠ tool_calls ≠ 最终答案 —— Hermes 拦截，转入执行
💡 模型说「我要用工具」，执行却轮不到它 —— 先过秘书这一关
STEP 4步骤 C · 调外包

调外包

Hermes 解析意图，去请求真正的 MCP Server 干活

mcp_result = call_mcp_server(tool_name, arguments)
🤖 Hermes
browser_open_url
⚙️ MCP Server
工具调用 · 实际执行
tool: browser_open_url
args: { "url": "https://hz-weather.gov.cn" }
→ 真实浏览器打开页面 ✓
✓ 老板（LLM）下令，外包（MCP）动手
💡 真正打开浏览器的是 MCP Server —— LLM 只负责下令与等待
STEP 5步骤 D · 塞回

塞回

MCP 的执行结果以 role:"tool" 追加进 messages —— 循环带着新情报继续

messages.append({"role": "tool", "content": …})
user帮我打开杭州市气象局官网，看看今天天气。
assttool_calls → browser_open_url(…)
tool{ "tool_call_id": "c_01", "content": "页面已打开 · 标题：杭州市今日天气" }
messages.length = 3 · 带着结果回到循环开头
💡 role:"tool" 是 LLM 看到「外面发生了什么」的唯一窗口
STEP 6循环与退出

循环与退出

LLM 可能继续点菜，也可能直接回答 —— tool_calls 为空才是终点

while True: … until no tool_calls → return content
2LLM 看完页面标题，又点菜 browser_extract_text → 执行 → 塞回（length = 5）
3LLM 拿到气温数据，直接组织回答 —— 本轮 tool_calls 为空
✓return content：「今天杭州 12–19°C 小雨，出门带伞」→ 交给结果返回层
✓ 退出条件只有一条：LLM 不再要求工具
💡 只有不带 tool_calls 的回复，才是给用户的最终答复

messages 即工作痕迹

每轮追加、永不覆盖 —— 谁说了什么、工具回了什么，全在这一个数组里

🚪
退出条件只有一条
