STEP 1KV Cache

好记性不如烂笔头

每生成一个新字，都要「看」前面所有字的注意力 —— 算过的别扔，存下来只追加

Key/Value 向量逐层缓存 · 每步增量追加
✕ 没有 KV Cache：每写一个字，全文重算
✓ 有 KV Cache：算过的存笔头，只算新字
~2 GB7B 模型 4k 上下文的缓存
~16 GB拉到 32k 上下文 —— 线性涨
1/10 价prompt cache 缓存的正是它
缓存随上下文线性增长 —— 这就是长上下文贵又慢的根源（02 期）；
Hermes 13 期说的 prompt cache，存的就是这份算好的 K/V，命中即跳过整段重算
💡 KV Cache 是「好记性不如烂笔头」的工程版 —— 也是长上下文账单的来源
STEP 2量化

权重从 16 位压到 4 位

每个数字少用几 bit 存 —— 显存省一大截，代价是「轻度模糊」

FP16 → INT8 → INT4 · 精度换显存
FP16 原始16 位精度 · 基准 显存 100%
INT8 量化8 位 · LLM.int8() 减半 · 几乎零损失
INT4 量化4 位 · GPTQ 1/4 · 175B 塞进单卡
实测：INT8 跑 175B 模型零性能损失、显存减半；INT4 让「一整台服务器」变「一张消费级显卡」
代价是轻度模糊 —— 常见任务无感，极端任务可感
💡 量化是把模型「从一机变一卡」的魔法 —— 自部署玩家的必修课
STEP 3投机解码

小模型起草，大模型批卷

小模型一口气草拟几个字，大模型一次并行验证 —— 收下对的，从第一处不对的地方重来

起草 ×N → 并行验证 → 1.5~3× 加速
🖊️ 小模型草稿 → 大模型验证
床前 ✓明月 ✓光，✓疑是 ✓地上霜 ← 大模型亲自写
匹配的四个直接收下，一次前向验证省掉四次排队 —— 且输出与直接生成完全一致（数学上无损，不改模型不重训）
教授一次批四份卷子，比逐份看快得多 —— GPU 天生擅长并行，投机解码就是把并行的便宜占满
DeepSeek-V3 训练时内置 MTP 模块，就是为这一手准备的
💡 无损加速的罕见案例 —— 白捡的速度，不要白不要
STEP 4MoE 混合专家

671 位在编，每次只请 37 位出诊

一支庞大的专家团队 + 分诊路由：每个 token 只激活其中一小撮

DeepSeek-V3：总参 671B · 每 token 激活 37B
671B总参数（在编）
37B每 token 激活（出诊）
2.788MGPU 时完成全量训练
调用 API 按「出诊量」付费 —— 同等能力更便宜更快；
自己部署则要把 671B 全装进显存，每次只用 37B 算 —— 省算力不省显存
💡 MoE 让模型「又大又快」—— 规模在编，精干出诊
STEP 5四件套协同

每一件，都在少算一点

四件套各管一个维度的浪费 —— 叠在一起，才有今天又快又便宜的推理

少重看 · 少占用 · 少排队 · 少请人
