01粒度

一把尺子，管多少个数

这是唯一的旋钮：组越大越省，组越小越准。

per-tensor最粗
per-128fp8 常用
per-32MXFP4
per-16最准

横条 = 贴合程度（组内数值分布越集中，尺子越贴身，量化误差越小）

没有「最优粒度」，只有「这一层的数值分布 + 这一层的 kernel 能不能吃」。
02算账

有效位宽，要连尺子一起算

每元素真实占几位 = 数据位 + 尺子位 ÷ 组大小。

fp4/324.25

fp8 per-128 = 8 + 8/128；fp4 per-16 = 4 + 8/16；fp4 per-32 = 4 + 8/32

per-16 比 per-32 多付 6.6% 的位宽 —— 换回来的精度，值不值要看这一层误差会不会累积。
03打包

四把尺子，塞进一个 int32

ue8m0 只有 8 位，四个正好填满一个 32 位整数。

一个 int32 = 4 把尺子 = 128 个 4 位数
一行 hidden=d 的 scale 序列 = d/128 个 int32 读取一次，就拿到 128 个数的尺子 （行主序 packed ue8m0）
打包不是为了省空间（8 位本来就不浪费），是为了让 TMA 一次搬完。
04共存

同一层里，三种粒度并存

一次 RMSNorm 的输出，要同时喂给三个下游。

输出去向粒度布局
attention（mxfp8）32行主序 packed ue8m0
fp8 GEMM128TMA 对齐，列主序可选
Mega MoE（x_sf）32按 BLOCK_M 分块 + 128×4 转置

同一个 kernel 里，三套 scale 用不同布局同时写出 —— 因为下游三个 kernel 要的格式不一样。

这就是「尺子」的隐性成本：不是算不出来，是要按每个下游的 tile 形状重新排一遍。
05边界

为什么不能无限细

再细下去，撞的是硬件和 kernel 的硬约束。

01 · 对齐
TMA 要求 128 对齐

尺子序列的起止必须落在对齐边界上，否则要拆成两次搬。

02 · 次数
per-16 要多读四倍

同样的 KV 长度，scale 读取次数从 1 次变 4 次，这部分也是带宽。

03 · 平台
有的芯片只认 32

换到 NPU 后端时，粒度会被固定成 32，代码里直接断言。

所以粒度不是一个数，是数值需求 × kernel 形状 × 平台的交集。
