## 二、结构性问题（比缺内容更该先修）

### S1 · 零导航：82 集没有任何一个可点击链接

实测：82 个动画里 **`<a>` 标签总数 = 0**。全文唯一的 `href` 是 12 个 `<link rel="icon" href="data:,">`（`inf` 系列的 favicon 占位），没有任何导航链接。
唯一出现 `index.html` 字样的是 `hermes-09` 里的一条演示日志（`docs/index.html ✓`），不是链接。

- `inf-01`～`inf-11` 末尾写了 `下一集：门口那三张脸，其实说的是同一句话。` —— 只有预告文案，**点不动**。
- 读者看完一集只能按浏览器返回键，或手动改地址栏。
- 单集被单独分享出去时，接收方找不到入口。

这是当前体验上最大的硬伤，且修复成本最低（每集末尾加两个 `<a>`，或用一小段脚本按文件名算上一集/下一集）。

### S2 · 没有知识地图

`index.html` 是 9 段卡片墙，按「板块」平铺，但没有回答：

- 应该从哪一集开始？
- 讲 Transformer 的三集（`ai-13-transformer` / `llm-05` / `ai-11`）谁先谁后？
- 想看推理服务，`inf` 和 `ai-14-speed`、`ai-15-kv-cache` 什么关系？

卡片墙适合「已经知道要找什么」的人，不适合第一次来的人。建议补一张分层地图（模型原理 → 推理服务 → Agent 工程）+ 三条推荐路径（初学者 / 后端工程师 / Agent 开发者）。

### S3 · 五组主题重复，其中一组几乎重拍

| 主题 | 涉及集数 | 重复程度 |
|---|---|---|
| 思考链 / 推理模型 | `ai-13-thinking`、`ai-16-reasoning`、`hermes-12-thinking` | **高（前两集约 4/6 屏同构）** |
| 上下文管理 | `ai-02`、`pat-04`、`dev-03`、`hermes-13-context` | 中 |
| 记忆 | `ai-07`、`pat-03`、`hermes-08` | 中 |
| MCP | `hermes-mcp`、`pat-05`、`hermes-16-mcp2026`、`mcp-cdp` | 中 |
| 推理加速 | `ai-14-speed`、`ai-15-kv-cache`、`ai-14-moe`、`inf-07` | 低（总览↔深入，有意为之） |
| RAG | `ai-08`、`rag-01`、`rag-02`、`rag-03` | 低（科普↔实战，有意为之） |

`ai-13-thinking` 与 `ai-16-reasoning` 的分镜几乎一一对应：

```
ai-13: 回答之前先写一页草稿 → 想得越久答得越对 → 思考时间是个可调参数
       → 不是所有问题都值得想半天 → 打表计费 → 先打草稿再交卷
ai-16: 直接交卷还是先列草稿 → 草稿纸上发生了什么 → 第二条变强的轴
       → 一个模型变成一条光谱 → Agent 时代思考与动手交替 → 变强的第二条轴
```

两集只在「草稿纸上发生了什么」「思考与动手交替」上有真正增量。建议：保留 `ai-16`（信息更全），把 `ai-13` 降级为「计费视角」补充集，或合并。

### S4 · 编号断层与命名不齐

- `ai-04`、`ai-05`、`ai-06` **三个号从未存在过**（git 全历史无删除记录，是当初直接跳到 07）。
- `hermes-mcp-animation.html` 没有编号，但在索引里排第 03 —— 唯一一个破坏命名规律的。
- 因历史编号撞车（`ai-13-thinking` vs `ai-13-transformer`），现在同一前缀下有两套序号，靠 `docs/index.html` 的分组兜着。这不是错误，但新读者会困惑。

### S5 · 没有搜索

82 集全靠肉眼找。静态页加一个 `<input>` + 前端过滤 `a.card` 的 `innerText` 即可，成本极低。

## 三、内容缺口

按「读者会问、但现在没有片子能回答」来排，比按学科分类更有用：

| 读者会问 | 现有可看 | 缺什么 |
|---|---|---|
| 同一个模型为什么有 base / chat / reasoner 三个版本？ | `ai-01` 只有一句「微调对齐」 | **SFT / RLHF / DPO 偏好对齐** |
| 训练一次要多少卡？卡之间怎么分工？ | 无 | **分布式训练**（DP/TP/PP/EP/ZeRO） |
| 32k / 128k 上下文是怎么做到的？ | `ai-02` 讲现象，`inf-08` 讲服务端重放 | **RoPE 外推 / YaRN / 稀疏注意力** |
| 训练数据从哪来、怎么洗？ | 无 | **数据工程**（清洗/去重/配比/合成数据） |
| FP8 / FP4 怎么压？精度掉多少？ | `ai-14-speed` 只有一屏 | 低精度深入（**第二季已备料**） |
| 多机之间怎么通信？通信贵不贵？ | 无 | **NVLink / RDMA / AllReduce / EP 通信开销** |
| 一次对话到底花多少钱？ | `inf-06` 讲算力配额，不算钱 | **容量规划与成本模型**（吞吐-延迟曲线、$/1M tokens、SLA） |
| 模型到底强了多少？怎么比的？ | `dev-04` 是工程可观测，不是模型评测 | **评测基准**（MMLU/数学/代码、LLM-as-judge） |
| 语音能用吗？ | 无 | ASR / TTS / 流式语音 |
| 视频生成呢？ | `ai-15-diffusion` 只讲图像 | 视频扩散 / 时序一致性 |
| 工具 schema 怎么从 OpenAPI 自动生成？ | 无 | 工具生态与版本管理 |
| 远程 MCP 的 OAuth 授权怎么走？ | `hermes-16-mcp2026` 一句「先解决你是谁」 | MCP 授权流程（OAuth 2.1 / DCR） |

### 已确认**不算缺口**的

- **CNN / RNN / 激活函数**：README 第 4、5 章确实没有对应动画，但那是 Vite 交互式应用的职责（`frontend/src/visualizations/ch04_*`、`ch05_*`），`docs/` 动画定位是 LLM/Agent 时代，不重复建设。
- **弹性与故障 / Kernel 层 / 批不变性**：规划书第八节已列为第二季选题，本次不重复计入。

### 导航的实现约束（供后续维护）

- **顺序唯一来源是 `index.html` 的卡片顺序**，不是文件名排序。系列内改顺序、跨系列挪动，重跑脚本即可。
- 注入块用 `<!-- epnav:start -->` / `<!-- epnav:end -->` 包裹，脚本每次先删后插，**幂等**；手工编辑会被覆盖。
- 定位为 `position:fixed` 左上角（`z-index:70`），刻意避开右侧 `.dots` 与底部 `.scr-foot`；实测 900px 与 375px 宽度下均不与 `.scr-head` 重叠。
- 回归：注入后全量重跑逐屏扫描，82/82 无 console 报错、无 `pageerror`。
