# 训练原理季 · 立项与素材说明

> 补的是 L1 训练层。`tr-` 前缀，01–06，共 41 屏。
> 索引：`docs/index.html` → 「训练原理 · 模型怎么来的」

## 一、为什么补这一季

整站知识地图是一条因果链：**训练 → 模型 → 推理 → Agent**。把 96 集按层级重新数一遍，最上游那一层是悬空的：

| 层 | 集数 | 占比 | 状态 |
| :-- | --: | --: | :-- |
| L4 Agent 工程 | 39 | 41% | 饱和（对象 18 + 进阶 7 + 避坑 5 + 工坊 6 + 模式 6，多个主题互相交叉） |
| L3 推理服务 | 31 | 32% | 饱和（三季 27 集已上线 + 4 集在排期） |
| L2 模型原理 | 17 | 18% | 基本够（结构、注意力、MoE、KV、位置、采样、多模态都有） |
| **L1 训练** | **4** | **4%** | **断链** |

而这 4 集本身也不成体系：

| 集 | 讲什么 | 缺口 |
| :-- | :-- | :-- |
| `ai-01-training` | 三部曲（预训练 → 微调 → 对齐）各占一屏 | 只有全景，没有细节 |
| `llm-02-loss` | softmax → 交叉熵 → 反向传播 → 梯度下降 | 只到「一次更新怎么发生」 |
| `ai-17-rlvr` | 程序判分、GRPO、蒸馏 | 只讲后训练的最后一段 |
| `ai-18-finetune` | LoRA、微调取舍 | 只讲「改小模型」 |

中间隔着五件必须讲、却一件没讲的事：

1. **数据从哪来** —— 模型吃的是什么，为什么「洗数据」比「改结构」更影响结果
2. **一张卡放不下** —— 671B 参数怎么塞进几千张卡，五种切法的通信代价
3. **为什么不炸** —— 显存五份开销、fp32 影子、warmup、loss 尖峰
4. **要不要更大** —— scaling law，以及它为什么被推理成本改写
5. **怎么变听话** —— SFT / 奖励模型 / PPO / DPO，人的判断如何一步步被固化

观众从 `ai-01` 直接跳到 `ai-13 Transformer`，会以为「模型是凭空长出来的」。

## 三、数据出处与可信度

沿用规划书的 A/B/C 分级：**A = 可从代码或公式直接算出**，**B = 公开技术报告**，**C = 示意，不代表具体实现**。

| 数字 | 值 | 级别 | 出处 |
| :-- | :-- | :-: | :-- |
| 预训练 token | 14.8T | B | DeepSeek-V3 技术报告 |
| 总参数 / 激活参数 | 671B / 37B | B | 同上；比值 18.1× |
| 训练卡数 | 2048 | B | 同上 |
| 并行排布 | PP 16 × EP 64 × DP 2 | B | 同上（ZeRO-1） |
| 训练显存（7B） | 14+14+28+28+28 = 112 GB | A | bf16 权重/梯度 + fp32 主权重 + Adam m/v |
| 推理显存（671B，fp8） | 671 GB | A | 1 字节/参数 |
| 训练总显存（671B） | ≈ 8.7 TB | A | 13 字节/参数（1+4+4+4） |
| 最少卡数 | ≈ 110 张 80 GB | A | 8.7 TB ÷ 80 GB |
| NVLink / IB 400G | 400 / 50 GB/s | B | H800 规格；IB 400 Gbps ÷ 8 |
| 流水线气泡 | (P−1)/(M+P−1) = 3/11 ≈ 27% | A | 4 段 8 微批 |
| 算力最优配比 | 20 token/参数 | B | Chinchilla (2022) |
| 实际配比 | 200× 以上 | B | Llama 3 等公开报告的「过度训练」做法 |
| 数据配比（代码 28% / 网页 26% / 数学 18% / 中文 16% / 书籍 12%） | — | **C** | 屏上已标「示意比例，真实配比是核心机密」 |
| Jaccard 0.8 判重阈值 | — | B | MinHash 去重的常用门槛 |
| warmup 2000 步、裁剪 1.0 | — | C | 量级示意，各家用值不同 |
| 90 天排期（14/42/14/7/14） | — | C | 按 671B 级别训练的量级估算 |

**C 级内容在屏上都有一句限定**，不冒充实测。这与第二季「FP4 有效位宽可手算」的做法一致：能算的给算法，不能算的标明是示意。

## 四、与既有 4 集的分工

- `ai-01-training` 保留为**入口全景**（三部曲一屏一个），新季负责**展开**。新季第 6 集结尾主动回指它，形成闭环。
- `llm-02-loss` 讲**一次更新**（前向 → 损失 → 反向 → 更新），第 3 集讲**十万次更新为什么不崩**，不重复。
- `ai-17-rlvr` 讲**程序判分**，第 5 集把它放进「人工示范 → 人工比较 → 程序判分」的演进线里，作为终点。
- `ai-18-finetune` 讲**改一个小模型**，第 5 集讲**改大模型的行为**，前者是后者的轻量版。

## 七、补集：`ai-21` 专家是被逼着分工的

补 L1/L2 交界处唯一还空着的一格：MoE 的前向已有 `ai-14`，但**路由是怎么在训练里被拉平的**没讲。这一集放在「AI 运作原理 · 深入篇」第 08 集（`ai-21`），不占 `tr-` 编号 —— 它讲的是模型内部的机制，不是训练流水线上的一道工序。

### 8 屏结构

| # | 屏 | 讲什么 |
| :- | :-- | :-- |
| 1 | 封面 | 256 专家 / 选 8 / 2 份偏置 |
| 2 | 一次打分，选八个 | 门控是一层矩阵；256 格点阵只亮 8 格 |
| 3 | 谁先跑起来，谁就一直跑 | **3D 高度场**：平 → 6 根尖峰 → 压回平面，循环演示 |
| 4 | 拿损失函数拉住它 | CV² 公式、α = 1e-4、α 太小/太大两端的代价、2.0 与 0.0001 的量级对比 |
| 5 | 只改「选谁」，不改「给多少」 | noaux_tc：E12 分数最高却被 −0.02 挤掉；偏置不参与加权 |
| 6 | 偏置跟着权重一起发布 | 代码证据：两个 FP32 偏置参数、门控不进 fp8 |
| 7 | 训练调平了，请求不让 | EPLB：一个原位 + 三个副本、窗口 100 步、首次重排提前 1/4 周期 |

### 视觉上返工的地方

1. **3D 高度场第一版颜色是彩虹**：`setHSL(0.74 − 0.74n)` 在紫→红之间穿过了蓝、绿、黄，中间高度全部变成青色，看起来像三种东西。改成只走 `0.70 → 0.95` 一小段（紫→洋红→粉红），和本幕主色也接得上。
2. **阶段标签按 q 阈值判断**：q 在平台期是 1，直接命中了「加了修正」那一档，导致峰值时显示错误文案。改成按时间轴 x 的五段判断。
3. **点阵初版 32 列 × 8 行**：单格只有 13px，整块太扁，页面上下空。改成 16 × 16 大格（320px 见方），也更像「256 个专家」的一片。
4. **α 的权衡尺两段渐变中间断开**：中段用了 13% 白，读起来像两根条。改成红→洋红→琥珀的连续渐变，并把 α 标记正好落在洋红那一档。
5. **槽位图初版有两个「原位」E17**（GPU0 和 GPU1 都标成原位置）。改成一个原位 + 三个副本，语义才对。
6. **`✓` 在中文环境下回退成 `√`**（已多次踩到）：结果列改成「选中 50%」纯文字。
