# 从「亚马逊申诉合规助手」PRD 提炼 Agent 工程模式 · 分析与选题

> 分析时间：2026-11-04 · 输入：`D:\work\erp-docs\lingxing-erp\PRD-亚马逊申诉合规助手.md`（v0.3，海星 ERP 静态演示原型）
> 一句话定位：**PRD 讲的是亚马逊申诉，能教的是通用 Agent 工程模式。** AI-Insight 不复刻这个产品（它本身就是另一个项目的静态原型），而是把里面已经想清楚的机制——多 Agent 分工的成立条件、事实状态机、证据链、护栏分级、重复失败升级——提炼成教学集与可运行示例，反哺 pat/dev/rag 三条线。

## 一、PRD 里值得教的机制盘点

逐条对照 AI-Insight 现有 113 集，标出「已有铺垫 / 缺口」：

| PRD 机制 | 通用原理 | 现有铺垫 | 缺口 |
|---|---|---|---|
| 六 Agent 接力（分流→资料→材料→文稿→质检→提交），棒与棒之间是**人工确认点** | 流水线型多 Agent：分工何时成立 | hermes-17（"一群智能体反而更差"+三个成立条件）、pat-01 Plan-and-Execute | **"分工+闸门"的正面案例**：错误不可逆（对外提交）× 每段有独立验收标准 × 确认点隔开——hermes-17 的成立条件的具象化 |
| 问题类型/处理阶段/回应立场/提交形式**四个正交字段**，不是 A/B/C/D 互斥路线 | 正交设计 vs 路线硬编码 | 无直接对应 | 标签是分流提示不是路线；组合空间（如"账户关联+上轮拒绝+部分争议+文本附件"） |
| 事实状态机：待核 → 已核 → **来源冲突即暂停生成**；占位符保留到人工清零 | 幻觉防护的工程化 | dev-03 上下文工程、hermes-20 三道保险丝 | **"未核实的输出不许生成"**作为流程 gate：不是提示词约束，是状态机+闸门 |
| **证据链**：主张 → 材料 → 材料中可核内容 → 来源 → 支持范围；只有文件名不算证据链 | 证据引用是一等公民 | rag-03（拒答与强制引用）、rag-05 GraphRAG | **链式完整性检查**：每份附件双字段（材料内容+支持的事实/论点），正文自动编号引用，缺链即阻塞 |
| 通知点名材料 vs 案型建议材料 | 本体里的「必需」vs「建议」属性 | rag-kg-ontology-research（TBox/ABox） | 现成的本体教学素材：通知→要求→材料→事实 就是一条图路径 |
| 六维对比 + "未找到合格样本"显式记录，不得虚构样本编号/通过率 | 检索结果的证据等级 | inf-25/27（评测口径）、dev-04 评估观测 | **检索质量 gate**：样本要能回指平台书面结果才算"已验证通过"，否则降级 |
| 阻塞 / 提醒 / 不适用 / 本轮不处理 **四态**；同类门槛不可用例外解除；总检独立校验 | 护栏不是一条线，是分级 gate | pat-06 软硬护栏、hermes-14 Hooks | 四态语义 + 阶段化清单（未到的阶段不显示检查项）+ 绕不过的总检 |
| 同模板拒信：第 2 次要求记录变化维度，第 3 次停止原入口转升级 | repeat detection 的领域版 | guards.py 的 repeat detection、hermes-18 checkpoint | 重复失败的**升级策略**：不是重试，是换问题问 |
| 轮次快照只读（每轮提交独立归档，审核退回开新轮不覆盖） | 事件溯源 / checkpoint | store.py 检查点、inf-23 确定性 | "档案是 append-only"的审计价值 |
| 通知/维度/材料/附件一变，申诉信草稿**即失效** | 依赖变更 → 缓存失效 | 无直接对应 | 生成物的失效条件要显式声明 |

其中教学价值最高、且现有系列完全没有覆盖的是三个：**证据链、事实状态机、护栏四态**。

## 二、动画选题（按系列归属）

### P0 · dev-06《证据链》——把"有文件"和"能证明"分开

- **一句话**：一条链 = 主张 → 材料 → 材料中的可核内容 → 来源 → 支持范围；断在任何一环都不构成证据。
- **分镜草案（7 屏）**：① 封面：一摞文件 vs 一条链；② 只有文件名为什么不算（"已上传"≠"已核实"）；③ 五环链展开，逐环点亮；④ 双字段：每份附件必须写"材料内容"+"支持的事实/论点"；⑤ 通知点名（必需）vs 案型建议（建议）——本体的两类属性；⑥ 缺链即阻塞：正文自动编号引用与附件顺序一致；⑦ 收口：引用不是装饰，是链路——呼应 rag-03 的拒答引用。
- **衔接**：rag-kg-ontology-research 第六节预埋了这个选题；rag-demo 的古诗文语料可直接当屏上演示数据（"《静夜思》是李白写的"这条主张，链条上每环是什么）。

### P1 · dev-07《不知道就说不知道》——事实状态机

- **一句话**：待核 / 已核 / 冲突暂停三态 + 占位符清零 + 生成即失效——把"不要编"从提示词搬进状态机。
- **分镜草案（6-7 屏）**：三态流转图；来源冲突即暂停（通知说 A、后台说 B）；占位符为什么不能自动补；生成物失效条件（输入变了草稿就是旧的）；"暂未发现冲突 ≠ 平台确认属实"。

### P1 · pat-07《接力，不是合唱》——流水线型多 Agent

- **一句话**：hermes-17 说一群智能体往往更差；这个 PRD 展示分工什么时候对——错误不可逆 × 每段独立验收 × 人工闸门隔开。
- **分镜草案（7 屏）**：六棒接力图，每棒标注输入/输出/验收标准；确认点 = 阶段墙；与单 Agent 主循环对比（HERMES 拆解系列）；什么时候退回单 Agent。

### P2 · dev-08《不可绕过的门》——护栏四态与总检

- 阻塞/提醒/不适用/本轮不处理；未到的阶段不显示检查项；总检独立校验，隐藏检查项不放行。呼应 pat-06（软硬护栏）——那一集讲"哪层软哪层硬"，这一集讲"门有哪些等级、谁有权开"。

### P2 · pat-08《标签不是路线》——正交维度

- 四个可组合字段 vs 互斥路线；旧 A/B/C/D 编码仅历史兼容。偏产品设计，适合与 pat-07 合并或单独做短集。

### P2 · 《第二次拒绝开始复盘》——重复失败升级

- 同模板拒信 2 次记变化维度、3 次停止原入口；轮次快照 append-only。可与 hermes-18/harness 线合并讲，不一定要新开。

## 三、demo 选题：`examples/appeal-flow-demo/`

对照 `examples/agent-harness-demo/`（01–09 已成型）的体例，新建一个**零 LLM 依赖、pytest 可测**的工作流演示包——PRD 的机制全部可以规则化，正好展示"不是所有 Agent 应用都要先接大模型"：

```
examples/appeal-flow-demo/
├── README.md            # 与 PRD 机制一一对应的导览表
├── _common.py           # FakeLLM（规则式）、案件状态 dataclass、维度字段
├── 01_triage.py         # 分流：四维收集 + 案型候选；证据不足 → "待识别案件"不硬猜
├── 02_evidence_gate.py  # 证据链缺口矩阵：通知点名 vs 案型建议，缺链即阻塞
├── 03_position_draft.py # 五种回应立场 → 五种文稿结构；部分承认拆两段；纯视频出准备卡
├── 04_rejection_loop.py # 同模板拒信计数升级（2 次记变化、3 次停）+ 轮次快照 append-only
└── test_appeal_flow.py  # 每个脚本至少 2 条断言，接入现有 pytest
```

- **与 harness-demo 的关系**：那 9 个脚本讲"单个 Agent 怎么跑得稳"；这 4 个讲"一圈 Agent 怎么分工守门"。README 里互相引用。
- **为什么不用真 LLM**：PRD 的价值全在流程控制（状态机、闸门、计数），规则式 FakeLLM 足够演示，且零成本、CI 可跑。

## 四、实施建议与不做的事

**最小高价值组合（若做）**：dev-06《证据链》+ `examples/appeal-flow-demo/`（四个脚本）先行——动画有 rag 线强衔接、demo 与 PRD 验收标准逐条对得上；之后按需补 dev-07 与 pat-07。

**明确不做**：
1. 不复刻申诉助手本身（海星 ERP 项目在做静态原型 `/compliance/amazon-appeal`，AI-Insight 不做第二份）。
2. 不讲亚马逊业务规则（F1–F12 案型、站点政策）——那是领域知识不是 AI 原理，屏上只作为"某合规场景"的示意出现。
3. 动画中不出现可被理解为申诉建议的内容；案例编号与情节全部虚构并标注（与 PRD 第 74 行的处理一致）。

**待确认后开工**：动画走既有流程（写集 → index/计数 → nav-gen → playwright 全屏截图验收）；demo 走 harness-demo 体例（脚本 + README + pytest），两样都过现有 CI。
