SEASON 3 · 09 · 幕 C 时延

二十万个数
只留一个 id

logits 进来是一条长河，出去的只有一个 token id
采样是生成前的最后一道工序

向下滚动 · 先数一数朴素做法要跑几步↓
01 · 朴素做法

七步，七次发射

每一步都是一个独立 kernel，
每一步都要把 20 万个数完整搬一遍显存。

temperature20万
→
top-k20万
→
top-p20万
→
min-p20万
→
重复惩罚20万
→
log-softmax20万
→
采样20万
7
每步的 kernel 发射次数
×7
长河被来回搬的遍数
这里的"搬运"比"计算"贵——20 万个数过一个 kernel，多数时间在赶路
decode 每步都要采一次样。这条流水线每多走一步，都是乘以几千步的账。
02 · 融合

一段流水线，一次走完

fused_sample 把 temperature、top-p/top-k、
log-softmax、采样压进同一个 kernel。

fused_sample · 一次发射
temperaturetop-ktop-pmin-p重复惩罚log-softmax采样
7 段
朴素：数据来回赶路
1 段
融合：数据就地不动，流程走过去
省的不是算力，是七次往返的搬运和发射
采样只占一个 token 的一小段时间，但它每步都跑——乘上步数，就是可感的差别。
03 · 随机流

draft 和 target 不能共用一条随机流

tag 不是默认值时种子会偏移——
给每条流一个命名空间。

tag=draftseed ⊕ offset(draft)→ 流 A
tag=targetseed ⊕ offset(target)→ 流 B
⚠️
共用会发生什么

验证那一步会把 draft 自己"猜中"的结果再读一遍——命中是假的，接受率虚高， speculative decoding 白做。

🏷️
tag 是一层隔离

同一个 seed，tag 不同，偏移就不同——两条流不相遇，验证才拿的是真随机数。

随机性也要有边界：谁用哪条流，写进种子，不靠自觉。
04 · 确定性

换个批大小，还是同一个 id

输出只依赖 (seq_seeds, sample_positions, is_nextn_predict)——
与批大小、行序无关（回扣 S2-23）。

✓ 在依赖里

seq_seeds 每条请求自己的种子
sample_positions 采样的位置

✗ 不在依赖里

批大小、行序、这一批里的邻居是谁

这是"可复现"的工程定义：种子一样、位置一样，不管谁跟谁排在一批，结果逐位一样。
05 · 收束

幕 C 的最后一笔

换来守住
七次搬运 → 一次每步发射省 6 次
tag 隔离随机流验证不假通过
只依赖种子与位置批大小与行序无关
至此幕 C 收官：发射（cudagraph）、装箱（metadata）、采样（sampler）——
时延的固定开销，三处都钉死了
数据出处：tilelang_ops/fused_sample.py、layers/sampler.py。
