STEP 1从硬编码到外挂

策略不该焊死在主循环里

Hermes 09 期的三级权限闸写死在运行时代码中：换团队、换红线，就得改 Agent 本身 —— Hooks 把这些检查点开放出来

✕ 老做法：改策略 = 改 Agent 代码

「禁止 rm -rf」「写文件后自动格式化」全部硬编码；多套环境共用一份运行时，策略分叉只能维护多个分支，升级时互相踩脚

✓ Hooks：在生命周期上挂自己的脚本

宿主在固定事件点执行团队提供的 shell/HTTP 脚本：退出码决定放行还是拦截。Agent 主程序一行不改，策略随配置走

💡 类比 Web 框架：中间件 —— 请求进、响应出的固定切面，业务代码与横切策略各管各的
STEP 2事件全景

一次会话里，有哪些挂点

Hooks 挂在会话与工具调用的关键时刻，Pre/Post 是最常用的一对

SessionStart

会话开始：注入项目上下文、加载环境信息

UserPromptSubmit

用户消息提交前：补充规范、追加必须遵守的规则

PreToolUse

工具执行前：拦截命令、校验参数（最核心的安全闸）

PostToolUse

工具执行后：自动格式化、扫描输出、写审计日志

Stop / SubagentStop

本轮（或子代理）结束：检查是否真的完工、收尾通知

💡 这就是 Hermes 01 期「适配层 + 主循环」之外的第二条横切线：横切策略有了统一插桩点
STEP 3PreToolUse 的四种决定

一个退出码，四种去向

钩子脚本跑完，用退出码与结构化输出告诉宿主怎么处理这次工具调用

hook(tool, args) → exit code + JSON → 宿主执行决策
PreToolUse: bash({ cmd: "rm -rf ./build" })
allow · 0直接放行，用户无感
deny · 2阻断并返回原因，模型看到「被拒」后改路（09 期：模型只有提案权）
ask转人工确认，走三级权限的黄灯
modify改写参数：自动补超时、规范路径，再放行
💡 决策由宿主代码执行，模型无法绕过 —— 比「在 system prompt 里恳求它别做」可靠一个数量级
STEP 4钩子都在干什么

把团队规矩变成确定性动作

🧹 自动善后

PostToolUse：编辑文件后自动跑 prettier、测试后收集结果

🚫 强制策略

PreToolUse：危险命令、外网域名、删除操作一律拦或升级

📥 注入上下文

提交提示时带上分支名、规范文件、当天环境差异

📜 审计留痕

每次工具调用落盘（谁、参数、结果）—— 与避坑 04 的 trace 合流

🔁 完成校验

Stop 前跑测试门禁：不绿不算完，自动打回

🚨 异常上报

命中敏感模式（私钥、~/.ssh）立即阻断并通知（09 期红线清单的工程化）

💡 凡是「无论模型怎么想都必须成立」的规矩，都适合下沉为 hook，而不是写进提示词
STEP 5钩子的边界

它不是第二个模型

宿主侧（hook）确定性脚本：快、可复现、可审计；失败默认拒绝
模型侧只看到 hook 返回的结果文本，看不见脚本内部，也无法关闭它
三条工程红线
① fail-safe：hook 超时或报错，默认 deny/ask，绝不静默放行；
② 幂等可重入：重试与事件重复触发时不能产生副作用叠加（参考 11 期幂等原则）；
③ 返回可行动错误：拦截原因写清楚，模型才能据此改路（避坑 01）。
💡 权限防的是模型乱来，hook 防的是规矩被遗忘 —— 一个是闸门，一个是让闸门可插拔的插槽
RECAP全景

生命周期上的确定性插槽

事件挂点 → 宿主脚本 → allow/deny/ask/modify → 善后与审计，策略随配置走

事件→hook 脚本→退出码决策→执行/反馈→审计
🎬
在固定时刻插桩

SessionStart / UserPromptSubmit / PreToolUse / PostToolUse / Stop —— 不改主循环即可挂入团队策略

🚦
退出码即闸门

allow/deny/ask/modify 四种决策由宿主强制执行，模型只有提案权；拦截原因反馈成下一轮观察

🛡️
确定性 + fail-safe

自动善后、强制策略、审计留痕全部可复现；hook 是宿主脚本不是模型，超时出错默认拒绝
