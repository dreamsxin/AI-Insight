01契约

只由三样东西决定

采样函数的输出，被写死成这三个输入的纯函数。

RANDOM_SAMPLING · 契约
seq_seedsample_positionis_nextn_predict
→ 输出 token 下标，与 batch 大小、行序无关

注意这里没有「batch 里第几行」这个输入 —— 它根本不应该参与计算。

这条契约一旦写进注释，就变成了可测试、可回归的工程承诺。
02打乱

换个顺序，结果也跟着换位置

行顺序变了，每行的结果不变 —— 只是位置挪了。

A
#2
B
#0
C
#3
D
#1

打乱后：B 仍然出 #0，A 仍然出 #2；把任意一行单独拿去跑，结果也一样。

这才是「可复现」：不是整体跑两遍一样，而是任意切分都得出同一个字。
03为什么会不一样

浮点加法不满足结合律

换个顺序加，末位就会差一点；差一点，argmax 就可能翻。

(a + b) + c ≠ a + (b + c) // 差在最后几位 logits 只差 1e-7 → softmax 之后仍然只差一点点 但 top-1 的两个候选本来就咬得很紧 → 直接换个 token
关键
不是精度不够，是顺序不固定

同样的数，换一种加法规约，末位就不同。

大模型输出本来就是概率上接近的两个候选，末位噪声足以改变结果。
04三个来源

谁在偷偷改变加法顺序

01
规约方式

通信时把一次大归约拆成多段，段数随负载变 → 加法树形状变。

02
GEMM 分块

batch 形状变了，tile 边界跟着变，累加顺序也就变了。

03
专家位置

EPLB 把专家挪到别的卡，token 的累加顺序随之改变。

三条里最隐蔽的是第三条：负载均衡本身就会破坏可复现性。
05开关

打开它，要关掉两样东西

工程里就是一个环境变量，但代价写在别处。

BATCH_INVARIANT = 1 → 通信 Layer：禁用多段归约 （allow_multiple_reduction = False） → 专家重排：必须关掉 （否则权重位置一变，累加顺序就变）

反过来看，这行代码恰好说明了：EPLB 与批不变在机制上互斥。

所以它不是「默认开」的 —— 生产环境更在乎吞吐。
