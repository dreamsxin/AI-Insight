STEP 1先看直线 RAG 的假设

一次检索，定生死

工坊 01–03 的经典链路：问题只检索一次，命中就答、没命中也硬答 —— 它假设「top-4 里一定有答案」

问题 → 向量库 top-k → 塞进 prompt → 回答（没有回头路）
用户问题→ 检索一次→ 照单生成

✕ 三种翻车现场（工坊 03 已埋过伏笔）

问题问的是最新消息，知识库里没有；型号写成 SX-200，向量库飘走；问题其实要查数据库/算数，却被当成文档问答 —— 检索没中，生成照样编

库外/时效问题问法漂移需要精确计算多跳推理
💡 经典 RAG 是开卷考试但不许翻第二次书 —— Agentic RAG 让模型能判断「这页没用，换一本查」
STEP 2查询路由：先分诊再检索

不是每个问题，都该查向量库

Agentic RAG 的第一步是加一个分诊台（可用小模型或规则）：先判断问题类型，派发给最合适的数据源

router(问题) → 向量库 / BM25 / Web / SQL / 直接回答
「A 套餐退款政策和上周销售额分别是多少？」
📚
向量库退款政策等语义问题
🌐
Web 搜索时效、库外信息
🗄️
SQL/表格「销售额」要算
💬
直接回答寒暄无需检索
一次问题可以同时派给多条管道（并行），再由主循环汇总 —— 这正是 Hermes 17 期说的：按任务性质选工具，而不是万物皆向量
💡 路由让 RAG 从「一个检索器」变成「一个会选数据源的 Agent」—— 分诊错了，后面全错
STEP 3CRAG：检索结果先体检

查回来的资料，敢不敢用？

CRAG（Corrective RAG，纠错式检索）给检索结果打一个置信度分，像红绿灯一样决定下一步：用、换路、还是两手准备

● 高置信

绿灯：精炼后用

资料确实相关 → 去掉噪声、提炼要点，再交给生成

● 低置信

红灯：弃用，上网

库里没查到靠谱的 → 整批丢弃，改走 Web 搜索兜底

● 模棱两可

黄灯：两条都走

拿不准 → 内部资料与网页结果都保留，生成时交叉对照

判分可以很简单：检索分数 + 与问题的重合度；低于阈值就触发兜底。检索 → 评估 → 再决策，本质就是 Agent 主循环在检索环节的一次应用
💡 经典 RAG 默认「捞上来的都是好货」；CRAG 先验货再下锅 —— 承认检索会失败，是纠错的前提
STEP 4Self-RAG：边写边给自己贴标签

回答的每一句，都要有出处撑腰

Self-RAG 让模型在生成过程中插入反思标记，像审稿人一样自问自答：要不要查、这段相关吗、有证据支持吗

三个自问

Retrieve？
这句需要查资料吗
IsRel？
捞回的段落与问题相关吗
IsSup？
我的回答被证据支持吗

对应动作

需要 → 先检索再写
不需要 → 凭常识直接答
不相关 → 丢掉重查
不支持 → 换说法或补检索，
拒绝无据硬编
它把「检索→生成」的单行道变成多轮小循环：写一句、核一次、不够再查 —— 与推理模型的思考链（AI 16 期）是同一种自我检查精神，只不过检查对象是证据
💡 CRAG 在检索后把关，Self-RAG 在生成中把关 —— 一个查货，一个验菜，可以叠加使用
STEP 5并行调用与成本账

Agentic 很好，但不是免费午餐

每多一轮检索/评估都是额外的模型调用与延迟 —— 工程上用并行省墙钟，用阈值控次数

⚡ 并行取数

多个数据源/搜索词用 asyncio.gather 同时跑，再汇总；墙钟时间取决于最慢的一路

🧮 代码当工具

算数、排序、结构化提取直接交给代码沙箱执行，不让 LLM「估」一个数

🛑 重试上限

检索-纠错最多 N 轮，超过就转人工/如实说不知道，避免空转烧钱

什么时候根本不用上 Agentic？
知识库很小、问答直接：约 20 万 token 以内的资料直接塞进提示词 + 缓存最便宜；FAQ 式问答，经典 RAG + rerank（AI 19 期）就够。多跳、时效、需要交叉验证时，Agentic 才值回票价
💡 和 Hermes 17 期同一条账：复杂度要花得值 —— 先证明直线方案不够，再给流水线装方向盘
RECAP全景

从一次检索，到检索的 Agent 循环

路由分诊 → 置信度体检 → 反思标签 → 并行取数 → 阈值收敛

分诊路由→多路检索→CRAG 体检→Self-RAG 核证→有据回答
🚦
先分诊，再验货

查询路由按问题类型选数据源（向量/Web/SQL/直答）；CRAG 用置信度三档决定精炼、上网兜底或双路并存

🔍
生成中持续核证

Self-RAG 的 Retrieve/IsRel/IsSup 标签让模型边写边查、无据不答；它是主循环在检索场景的特化，不是新模型

⚖️
复杂度按量付费

并行调用省墙钟、代码工具做计算、重试设上限；小库直接塞 prompt，只有多跳/时效/交叉验证才值得升级到 Agentic
