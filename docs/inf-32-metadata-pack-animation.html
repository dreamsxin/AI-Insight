装箱单先解决"怎么摆"。

02 · 字段语义

单子上的四栏

每个字段都回答一个具体问题。
最容易被读错的是 positions。

字段回答的问题
input_ids原始的变长序列——装箱前的货
positions每个 token 在未压缩序列里的位置——不是缓存里的下标
valid_token_mask哪些格子是真货，false 是 padding
num_reqs真实请求数——不含垫出来的行
positions 一旦按"压缩后的下标"理解，压缩层和 RoPE 就会整体串位
四个字段各管一件事，混用任何一个，错法都不一样。
03 · CP-mirror

重新排，也要能排回去

上下文并行时，token 被重新分到各 rank。
mirror_cp_index 记"怎么排"，mirror_cp_reverse_index 记"怎么还原"。

rank 0t0t2t4t6-1
rank 1t1t3t5t7-1
还原t0t1t2t3t4 · t5 · t6 · t7
-1 表示 padding——不是某个 token 的下标。把 -1 当成真下标用，就会去读不属于它的位置
排出去的每一格，都要能靠 reverse 索引原样收回来——收不回来，各 rank 的结果就对不齐。

05 · 清理

复用之前，先擦掉上一批的字迹

复用 cudagraph 时，"forward 里会重算"的字段
必须先清成 None。

# 复用图之前 get_clean_list() → 列出需要清空的字段 for f in clean_list: setattr(meta, f, None) # 不能留着上一批的值
🧼
为什么是 None 而不是 0

0 是一个合法的值（第 0 行、位置 0）。None 才能在下游被识别成"待重算"，触发正确的重建。

☣️
不清会怎样

mask、索引里留着上一批的残留——kernel 按旧形状算新的一批，错得没有规律，也难查。

装箱单是公用的纸：每批货上新单子之前，旧字迹必须擦干净。
