STEP 1典型架构

入口池与 worker 池，是两拨人

LangGraph Server 的分层实锤：API 池只收请求入队、从不执行 Agent 代码

API 按请求量扩 · worker 按积压 run 数扩 —— 两池独立
API 入口池

收请求 → 入队 → 返回任务号 —— 一行 Agent 代码都不跑

任务队列

pending run 排队 —— 积压深度就是扩缩容的仪表

Worker 池

认领任务 → 获取 lease → 加载对话 → 执行 → checkpoint 写库

外置状态

Postgres 存对话/执行/checkpoint；Redis 只当摇人铃（唤醒/取消/流转发）

一个用户字节都不进 Redis —— 它只负责「摇人」，不负责「记账」
💡 池子分开扩 —— 请求暴涨加入口，任务积压加 worker
STEP 2状态外置

worker 身上不能有状态

状态在实例内存里 = 换机即死 —— 集群的第一原则就是把它请出去

无状态 worker —— 一台就能照看数百万个执行
✕ 状态放实例内存

MemorySaver 重启即失，官方明说「不适合生产」；实例一挂，对话与执行全部蒸发；也无法扩缩容（一缩就丢用户）

✓ 状态外置到 Postgres

凭 thread_id 恢复任意对话；worker 只是「代驾」—— 被驱逐随时换人接手，一台 worker 可照看数百万个进行中执行

便利店的比喻：店员随便换，账本必须交接 —— Temporal 的「安全驱逐 + 异机恢复」就是这句话的工程实现
💡 worker 无状态 —— 所以集群才敢随便加减人
STEP 3黏性 vs 叫号

会话派给谁，两种模式

主流是「叫号」—— 但黏性作为延迟优化也真实存在

session_affinity TTL 3600s · 驱逐后回源重建
🏦 取任务即拉上下文（主流）

银行柜台叫号：谁空谁上，你的档案在库里不在柜员手里——worker 认领 run 后凭 lease 从 Postgres 加载，干完走人

💈 会话黏性（优化项）

熟客固定找同一个理发师：session_affinity 按会话 id 钉住实例（空闲 1 小时过期）；Temporal sticky 用内存缓存热执行——驱逐后回源重建

黏性是锦上添花的缓存，不是正确性依赖 —— 柜员休假，客人照样办得成业务
💡 正确性靠外置状态 —— 黏性只买回一点延迟
STEP 4扩缩容

看队列深度，加减店员

KEDA 盯着 Redis 队列长度 —— 积压多了加副本，空了缩到零

listLength 超标 → 按比例加副本 · 可从 0 起扩
📈
按积压扩容

队列长度超过 listLength 目标值 → 按比例加 worker 副本；activationListLength 设「从 0 起扩」门槛 —— 队列空时副本数可以是 0，第一个客人才雇第一个店员

🚪
缩容先优雅排空

摘出服务列表（不再派新活）→ preStop 钩子收尾 → SIGTERM → 30 秒宽限 → 到点才 SIGKILL —— 手里的活干完再走

🎚️
两池独立伸缩

API 池按请求量、worker 池按积压 run 数 —— 两个仪表盘，两个旋钮（17 期网关同理）

扩缩容的前提还是那句话：worker 身上没有状态 —— 有状态就缩不动
💡 队列空到 0 副本 —— 「零失业经济」由无状态化买单
STEP 5并发锁

同一本账，只许一个店员记账

每个会话同一时刻最多一个执行 —— 锁外置在队列层，不在任何实例内存里

认领前先获取 lease · Workflow ID 全局唯一
🎫worker-A 认领 thread-42 → 获取 lease（租约到手，开始执行）✓
🎫worker-B 同时认领 thread-42 → 队列层发现已被租约占用⏳ 等待
💥若不设锁：A、B 同时改同一份 checkpoint → 更新互相覆盖，账目错乱✕ 禁止
同类机制：Temporal 靠 Workflow ID 全局唯一 + Reuse Policy 杜绝双执行；自建可用 Redis SET NX PX（先到先得带过期）
不是信不过谁 —— 是两个人同时改一页账，必然丢更新
💡 锁外置在队列层 —— 实例挂了锁还在，换人接着干
RECAP全景

店员随便换，账本必须交接

双池架构 → 状态外置 → 叫号派发 → 队列深度扩缩 → lease 并发锁

入口/worker 双池→状态外置 Postgres→叫号 + lease→KEDA 扩缩→优雅排空
🗄️
无状态是集群的入场券

worker 不带状态才敢随时加减 —— 一台照看数百万执行的「代驾」

🧾
账本交接制

checkpoint 写外置库 —— 换机恢复、缩容排空，全靠账本不在人身上

🔒
锁外置在队列层

thread 同刻只跑一个 run —— 实例挂了锁还在，集群才靠得住
