STEP 2Token 爆炸

Token 爆炸

直接塞回 messages 的后果 —— 第一轮就会撞上上下文窗口的天花板

512,000 chars ≈ 250,000 tokens
原始返回 512,000 字符
≈ 250,000 tokens（含 HTML 标签浪费）
模型上下文窗口 128k需求 250k · 超出 95%
✗ 装不下 —— 请求直接失败
💡 直接塞回去，第一轮就会撞墙 —— 上下文窗口装不下
STEP 3瘦身三招

瘦身三招

Hermes 在喂回模型之前，先在 Server 侧把长文本处理干净

trim() · extract() · summarize()
✂️
截取trim

只留前 N 字符 —— 简单粗暴，适合「开头就有答案」的页面

🎯
提取extract

去掉标签与导航页脚，只留正文文本 —— 结构噪声一次清空

📝
总结summarize

调一次 LLM 生成摘要 —— 最省，但有一次额外调用成本

三招可以叠加 —— Hermes 按结果类型自动选择
💡 脏活累活都在 Server 侧做完 —— 模型永远看不到原始长文
STEP 4瘦身后

瘦身后

处理完的结果以 role:"tool" 塞回 —— 模型一屏读完，直接决策

messages.append({"role": "tool", "content": …})
tool 结果 · 瘦身后 · content
杭州今日天气：12–19°C · 小雨
明日天气：转阴 14–20°C · 湿度 78%
数据来源：杭州市气象局官网 · 更新于 09:00
✓ 2,300 字符 · 一次读完 · 直接可决策
💡 模型拿到的是「能直接决策的精华」—— 结论一个不少，废话一个不多
