STEP 1走一步，看一步

ReAct 很聪明，但也很费脚力

AI 05 期的 Agent 主循环：想一步 → 调一个工具 → 看一眼结果再想。短任务干脆利落，任务一长就开始绕路

while 没完成：思考 → 工具 → 观察（hermes-04 期）
💭 该先查什么？ → 🔧 搜 A 接口 → ✕ 字段对不上
↩ 绕路：这一轮的全部上下文下轮还得带着
💭 换个来源？ → 🔧 试 B 文档 → ✕ 版本过期
↩ 又绕：没有全局图，每步都在临时决策
💭 再想想… → 🔧 查 C 仓库 → ✓ 终于对上
上下文 token（每轮全量重发）92% · 账单滚雪球
💡 步数越多，每一步都越贵 —— 长任务需要有人先看地图
STEP 2规划器

一次调用，画出完整步骤图

Plan-and-Execute 先让一个 Planner（规划器）模型通读目标，产出有序步骤清单 —— 这一步只动嘴，不碰工具

goal → planner() → [step 1 … step N]，tools = []
🎯 用户目标「把这份报告
做成竞品周报」
→
🧠 Planner一次模型调用
不给任何工具
→
🗺️ 计划清单有序 · 可核对
PLAN · 5 STEPS
1提取报告中的关键数据与结论
2检索三家竞品本周的公开动态
3逐项对比，标出差异点
4按周报模板组织成稿
5自查数字与引用，交稿
规划时模型站在全局视角权衡依赖与顺序；计划还能先给人过目 —— 方向不对，在这一步就拦住
💡 规划只花一次钱 —— 一张清单换后面所有步骤不迷路
STEP 3执行器

领一条，做完一条

Executor 不重新思考人生，只领当前这一步 —— 每一步内部仍然是熟悉的工具调用循环

for step in plan：executor(step) → 观察结果
✓提取报告关键数据DONE
✓检索竞品 A / B 本周动态DONE
✓补齐竞品 C（官网无更新，查公告）DONE
逐项对比，标差异点　💭 → 🔧 → 👀RUNNING
套模板成稿并自查TODO
单行任务内部：想 → 调工具 → 看结果 该循环还循环（就是 04 期那套）；但每次只带这一步需要的上下文，干净、便宜、好重试 —— 第 3 步失败只重跑第 3 步，不必从头再来
💡 主循环没有消失 —— 它从「包打全程」降级成「打工一步」
STEP 4计划赶不上变化

撞墙了，带着真相回去重规划

执行中发现现实和计划假设不符 —— 硬走是错的，回流才是正解：把观察喂回 Planner，修订后续步骤

if 现实 ≠ 计划假设：replan(观察结果)

执行第 3 步的观察回传：竞品 C 官网改版，报价页 404 —— 此路不通
↑ 观察回流 PLANNER · 只重排未完成的步骤，已完成不返工 ↑
💡 好计划不是一次定终身 —— 是允许带着新证据修订自己
STEP 5怎么选

两种模式，各有各的地盘

没有谁更高级 —— 任务越长、步骤越可预判，规划越值；任务越短、越依赖临场试探，ReAct 越香

也可以杂交：大框架先规划，单步内部 ReAct
